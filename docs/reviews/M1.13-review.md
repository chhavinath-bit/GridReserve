```bash
cd infra && docker compose up -d --build --scale booking-service=2 --wait
cd ../frontend && npm ci && npm run typecheck && npm run lint && npm test   # 61 tests
npx playwright install chromium   # first time only
npm run e2e                       # 27 tests, about 1 minute
```

## 3. Explain it back

<details><summary>Why does each My bookings tab ask the server for its own list instead of filtering one list in the browser?</summary>
One list of 50 was split in the browser, so older bookings, or the nearest upcoming ones, could silently be missing. Each tab now asks for exactly its bookings in the right order (`status`, `from`/`to`, `order`), page by page with Load more, so nothing is left out.
</details>

<details><summary>Why build the Combobox ourselves instead of shadcn's?</summary>
shadcn's combobox needs the `cmdk` library, a new dependency needing approval. Radix Popover is already installed (`radix-ui`), and the filtering and keyboard handling are about 150 lines we fully understand and test.
</details>

<details><summary>How does the race test prove "one wins, one is told"?</summary>
Two browser contexts (alice and bob) select the same slot and press Hold together. Exactly one sees "Confirm booking", the other sees "This slot was just taken" and the slot now shows as taken. The database's exclusion constraint decides; the UI only shows the answer.
</details>

<details><summary>Two flaky tests appeared. What were they, and why weren't they retried?</summary>
The journey read the first free slot before the newly chosen day had loaded, and axe measured a slot's colour while its 120 ms fade was still running. Both are fixed by waiting for a condition (`aria-pressed=true` and no running animations). Retrying would have hidden a real timing bug in the test (CLAUDE.md: flaky tests are fixed, not retried).
</details>

<details><summary>Why does CI serve the app with `vite preview` on port 5173?</summary>
The refresh cookie only works when the request's `Origin` is the one identity trusts (`http://localhost:5173` in dev). `vite preview` serves the production build on that origin and proxies `/api` to the gateway, like the dev server.
</details>

## 4. Not proven yet

- Degraded mode in the browser with identity **really stopped**: the e2e test mocks a 503; the real outage is covered by the system tests (FS-33 admin list without names, FS-32..38).
- Screen-reader behaviour is checked by axe rules and keyboard tests, not with a real screen reader.
- The deployed site (M1.10 waits for the Oracle VM), so "every story demonstrable on the deployed site" waits too.
- Venue cards don't show how many bookables a venue has (the venue list API has no counts).
- The JS bundle is 700 kB (Vite warns above 500 kB); splitting admin into its own chunk is an option for M1.14.
