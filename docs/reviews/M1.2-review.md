Goal of this milestone: PostgreSQL itself refuses double-booking and member overlap, whatever the Java code does later.

## 3. Explain it back

<details><summary>1. Why an exclusion constraint instead of checking for overlaps in Java before inserting?</summary>

Check-then-insert is a race: two requests both check, both see the slot free, both insert. The constraint is enforced inside PostgreSQL at insert time, under concurrency, for every writer (service, script, psql). Java checks still give nice messages, but the database is the guarantee.
</details>

<details><summary>2. What does btree_gist add, and what does '[)' mean?</summary>

GiST indexes handle ranges (`&&` overlaps) but not plain equality on a bigint; btree_gist adds that, so one constraint can say "same bookable AND overlapping range". `'[)'` is half-open: the start is included, the end excluded, so 10:00–11:00 and 11:00–12:00 do not overlap.
</details>

<details><summary>3. Why does the bookable constraint use occupied_until but the member constraint end_time?</summary>

The buffer (cleaning, trainer rest) is the bookable's time, not the member's. Stored at insert, `occupied_until` also means a later buffer change never moves existing bookings (FR-CAT-12).
</details>

<details><summary>4. ddl-auto=validate: what does it do, and how do you know it is on?</summary>

Hibernate compares entities with the tables at startup and refuses to start on a mismatch; it never changes the schema (Flyway does). Proven by renaming a mapped column: startup failed with "missing column".
</details>

<details><summary>5. Why did the integration tests need Failsafe?</summary>

Surefire runs `*Test` in the `test` phase; `*IT` classes are run by Failsafe in `integration-test`/`verify`. Without the plugin the build is green and the 29 tests silently never run.
</details>

## 4. Not proven yet

- No Java code writes bookings yet: conditional updates, error mapping by constraint name (`409 SLOT_TAKEN`) and the per-member limit come in M1.5.
- Concurrency (50 parallel requests) is proven in M1.8; here each constraint is tested with sequential inserts.
- Opening hours, slot grid and durations are only stored here; enforcing them is service logic (M1.4–M1.7).
- The readiness check does not include the database.
